# 开发与审核流程

> 适用：本仓库所有功能开发（自 v0.10.0 起）。
> 执行方：PM（用户）+ 程序员（Claude Code）+ 外部审核员（另一 AI）。
> 本文件的角色、边界与协作规则由 PM 拥有，程序员必须遵守。

## 1. 角色、边界与协作规则

### 1.1 角色分工

- **PM（用户）**：有一定计算机基础知识，但非程序员。负责项目整体目标、提需求、手工测试（含 AX6 真机验收）、运行环境问题、提供云盘接口信息（官方文档 / 抓包 / 真实凭证）、守边界、拍板、控进展。与程序员用**交易语言**沟通（大白话；出现技术术语时程序员必须解释）。
- **程序员**（Claude Code）：写文档 + 写代码。对 PM 用**交易语言**汇报计划 / 进度 / 需求；仓库产物（代码 / commit message / docs / PROGRESS.md）= **专业语言**，给外部审核看。
- **外部审核员**（另一 AI）：审代码，只用**专业语言**与程序员沟通；PM 负责传接审核意见，不要求读懂内容。

### 1.2 范围边界（铁律，不可逾越）

1. **只做单账户单用户**（沿用现有 Basic Auth 体系），不考虑多用户/多租户。
2. **只做国内云盘**（天翼 / 移动 / 百度 / local），不接境外网盘（Google Drive、OneDrive 等）。
3. **只读 WebDAV**：不实现上传、删除、改名、写回云盘。
4. **接口行为证据分层**（云盘 API 多为非官方接口）：
   - 官方文档（如百度 OAuth）= 接口契约与预期行为的**首要依据**；
   - 真实客户端 / 官方 App 抓包、alist 运行记录 = 证明**特定客户端版本、特定环境**实际发生的行为；
   - 第三方源码（alist 等）只作理解、不作依据、不据源码猜测——与官方文档不一致时仅作排查线索；
   - httptest 假服务器 / 单元测试只证明本项目代码符合模拟契约，不证明真实云盘行为；
   - 官方文档内部冲突，或官方文档与真实客户端行为不一致时：记录客户端版本、操作条件与原始报文，交 PM 决策。
5. **运行环境硬约束**：x86 虚机开发、AX6 ARM64 真机验收；性能数据以 AX6 实测为准；发版 `CGO_ENABLED=0` 静态交叉编译。
6. **依赖铁律**：Go 标准库 only；`go.mod` 保持 `go 1.22`、零外部依赖，任何功能不得引入新依赖。
7. **架构禁区**：不改未加密路径的 302 行为；`TokenManager` / `HealthReporter` / `CredentialUpdater` 断言只针对原始驱动，包装层不得实现这些接口；`auth.StartWatcher` 只传 raw。
8. **关键不变量**：凭据状态必须互斥锁保护（getter/setter 访问）；offset/size 全链路 int64；state token 文件名 = 挂载名；config 与缓存 token 冲突时取较新者。
9. **密钥铁律**（Vault 上线后生效）：master key 永不传上网盘、必须离线备份；密钥丢失 = 数据不可恢复。

### 1.3 沟通协议（程序员 → PM）

1. **动手先说**：每开始一个新任务，先汇报「准备干什么、干到什么程度、需要 PM 提供什么、哪里不确定」，PM 点头后才动手。
2. **交易语言**：对 PM 的一切汇报用交易语言；必须出现的术语（如 `authorization`、`Range`、`manifest`）附一句大白话解释。
3. **不猜**：遇到「需求不明确 / 可能碰边界 / 有多个方案」三类情况，停下来问 PM，问了再动。
4. **收口必更 PROGRESS.md**：每完成一个阶段，同步更新 PROGRESS.md（专业语言），并在对话里用交易语言说明「更新了哪一节」。
5. **双听众分流**：对话框里对 PM 说的 = 交易语言；仓库产物（代码 / commit message / docs / PROGRESS.md）= 专业语言。程序员负责把专业结果「翻译」成交易语言讲给 PM；PM 只读翻译版。

## 2. 审核闭环（4 阶段）

1. **自查**：每完成一块，用 `/code-review` 自查，并额外对照铁律 + 关键不变量 + 架构禁区；阻断级问题先修。
2. **外部审核**：**每个功能一次**——功能完成后 PM push 到 GitHub 的 `feature/file-encryption` 分支（github.com/lamaged/mini-cloud/tree/feature/file-encryption），外部审核员审，拿回意见。**所有开发都在该分支进行，master 保持 v0.9.2 不动。**
3. **回灌 + 处置**：PM 粘贴意见并先说一句「下面是审核意见」；程序员把意见分五类（阻断 / 补充 / 可选 / 待拍板 / 驳回），用交易语言列「审核说了什么 + 打算怎么处置 + 风险」，PM 点头后才改、改完跑测试、再汇报。
   **驳回（独立判断义务）**：程序员对审核意见有独立判断义务，不得默认「审核说的就对」。若审核意见与铁律 / 关键不变量 / 实测事实 / 测试结果冲突，或会引入 bug / 回归 → 归入「驳回」类，给出具体依据。驳回不能单方拍板 → 升级 PM：用交易语言讲清「审核说 X，我认为 Y，依据 Z，风险 W」，由 PM 决定。纯技术对错 PM 无法判断时，把「程序员的驳回 + 依据」回给外部审核员复核（双向对话），争议未决前不得单方落码；确需先动，只动与该争议无关的部分。
4. **留痕**：每条意见必须有去向——已改 → PROGRESS.md；不改 → PROGRESS.md 记理由；待拍板 → TODO.md；技术债 → TODO.md；**驳回 → 升级 PM 并记 TODO.md「待 PM 拍板」直至裁决**。待拍板事项拍板后，须在 PROGRESS.md / TODO.md 记录最终决定及理由。下次 push 带上上次处置结果，避免重复提。

## 3. 开发闸门（6 道）

每个功能依次通过 6 道闸门，前一道通过才能进入下一道：

```
① 设计评审 → ② 实现 → ③ 代码审核 → ④ 测试门禁 → ⑤ 设备验收 → ⑥ 发布
```

### ① 设计评审

- [ ] 设计文档更新（docs/design.md 或独立文档）：目标、接口、流程、安全、验收标准。
- [ ] 明确**不改动范围**（如 302 路径、现有配置兼容）。
- [ ] 验收标准可测试、可观察。
- [ ] PM 确认批准后进入实现。

### ② 实现

- [ ] 新能力以可选接口 + 类型断言接入，不破坏现有类型。
- [ ] 凭据状态继续受互斥锁保护（getter/setter 访问）。
- [ ] 所有 offset/size 用 int64。
- [ ] 注释与用户可见字符串用中文。
- [ ] 不引入外部依赖（go.mod 保持不变）。
- [ ] 云盘 API 交互用 `httptest` 假服务器测试（含过期/403 场景），不依赖真实凭证。
- [ ] 遵守 §1.3 沟通协议（动手先说、不猜）。

### ③ 代码审核

- [ ] 自查：`/code-review`（effort: high）审 diff，修复确认的问题。
- [ ] 外部审核：PM push → 外部审核员审 → 按 §2 回灌处置闭环执行。
- [ ] 涉及以下任一，追加 `/security-review`：加密、凭证处理、新 HTTP 端点、文件写入。
- [ ] 人工复核：失败路径回滚是否正确；日志是否泄露凭证。

### ④ 测试门禁（x86 虚机）

- [ ] `go vet ./...`
- [ ] `go test ./... -race`
- [ ] 手工冒烟：local 驱动 + 浏览器验证新页面/新行为。
- 注意：先 `source env.sh`。

### ⑤ 设备验收（AX6）

- [ ] 交叉编译：`CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -ldflags="-s -w"`（发版加 UPX）。
- [ ] 部署前备份：旧二进制（保留为 `.prev`）、config.json、state/。
- [ ] 按该功能验收标准逐项在真机验证（功能 + 性能 + 内存）。
- [ ] 失败可回滚：换回旧二进制 + 备份 config，服务恢复原状。

### ⑥ 发布

- [ ] main.go 的 `version` 常量递增；README 变更记录更新。
- [ ] 文档同步（design / process / PROGRESS 如受影响）。
- [ ] git 提交并打 tag（如 `v0.10.0`）。

## 4. 回滚策略

- 每次部署保留上一个可用二进制（`mini-cloud-arm64-upx.prev`）。
- 凭证网页更新写入 config.json 前始终备份 `config.json.bak`。
- 回滚步骤：停止服务 → 恢复二进制与 config → 重启 → 验证根页面与挂载正常。

## 5. 环境速查

- x86 虚机：开发/测试机，`source env.sh` 后使用 Go 1.24.5。
- AX6：目标设备，静态交叉编译 + UPX 后 scp 部署；性能数据以 AX6 实测为准。
- 两套 config：虚机用 local 驱动测试；路由器用真实云盘配置。均被 gitignore。
