## 2. 独立审核补充（外部审"通过"未覆盖的两点）

### 2.1（P2）短重试对所有告警生效，永久性错误会反复短周期重扫

- **事实**：`if len(cwarns) > 0 { c.lastScan = now - scanTTL + scanRetryShort }`——只要本轮有**任一**告警（排队超时、manifest 损坏、保留名、子目录过多、非法路径…），下轮都缩短到 1 分钟。而"排队超时"这类**瞬态**才是设计目标，永久性错误本应维持 5 分钟。
- **实际影响**：懒刷新下，扫描只在"浏览容器路径 + TTL 到期"时触发，**不会自行每分钟跑**。因此永久错误最多在"用户反复浏览时"更频繁地重扫，而非常驻循环；CPU/API 代价有限。
- **建议**：可选优化——把短重试绑定到"瞬态告警"（排队超时 / 网络失败）用哨兵区分，永久错误维持 5 分钟；或引入简单退避。当前可接受，随下次触及该文件时处理。

### 2.2（P2）容器级 `raw.List` 失败不享受短重试（与子目录级不一致）

- **事实**：`scan` 中容器级 `raw.List` 失败走 `setContainerWarning + return`，**早于** `cwarns` defer 的注册，因此 `lastScan` 维持"5 分钟后"；而子目录级 manifest 失败走 1 分钟短重试。
- **影响**：容器级瞬态网络失败重试比子目录级慢。语义上可接受（容器 List 是单次调用、失败概率低），但建议加一行注释说明该分支有意不缩短，避免后续维护者误判为遗漏。
