## 2. 新增重要

### I8　默认配置会被写入 `.bak`，自愈可能把服务「恢复」成 admin/admin

- **位置**：`conf/config.go` / `Load` 的「文件不存在 → 创建默认配置」分支末尾的 `ensureBackup(path)`。
- **事实**：全新安装时 `Load` 先 `Save` 默认配置（`server.username=admin`、`password=admin`、一个 local 云盘），随后 `ensureBackup` 把这份**默认配置**复制成 `.bak`。用户随后手工编辑 config.json（加 vault 段/真实云盘）时写坏，重启自愈会用这份默认配置回退——**服务以 admin/admin 起来，且真实挂载全部消失**。
- **风险等级**：这是 I6 修复引入的副作用。修复前该场景是「启动失败」（服务不可用但未暴露）；修复后变成「启动成功但使用默认弱口令」，属**安全降级**。
- **要求**：
  1. 「创建默认配置」分支**不要**补 `.bak`（备份只应来自用户提供的有效配置；管理页写回时仍会自行备份）；
  2. 可加一道防线：自愈前若发现 `.bak` 是默认配置（`admin/admin` + 仅一个 local 云盘），拒绝恢复并报错提示手工修复；
  3. 补一条用例：`无 config → 首次 Load 生成默认 → .bak 不应被创建`。

### I9　README 的百度说明与 P11 后的行为不一致

- **位置**：`README.md` 已知限制（`af71273` 加入）：「**Vault 加密播放仅支持天翼 / 移动；百度挂载不支持 Vault（访问加密路径返回 502「不在支持范围」）**」。
- **事实**：P11 后 `loadRoot` 直接跳过百度（不建虚拟树），因此百度挂载上 `/backup` 是**普通目录**——既不会 403，也不会 502；`/backup/_mc/o/xxx.bin` 会按 302 直接给出 CDN 地址，**密文对象可被下载**（无密钥则无法解密）。
- **影响**：文档承诺的「502」不会出现，用户按文档排查会困惑；同时"密文可下载"这一副作用未记录。
- **要求**：README 改为「百度挂载不启用 Vault：加密目录按普通目录显示，`_mc` 密文对象可被直接下载（无法解密）」，与 `process.md 铁律 2` 的表述对齐；请 PM 确认接受该副作用。

## 3. 建议

| 编号 | 内容 | 建议 |
|---|---|---|
| P14 | P11 的「Reader 非 ReaderAt → 跳过」分支无测试 | 现有 `fakeRaw` 用 `memReader`（内嵌 `bytes.Reader`，实现了 `ReaderAt`），走不到该分支。建议加一个「返回不可 seek 的 `io.ReadCloser`」的假驱动，断言不建根、`List` 委托物理视图 |
| P15 | `.bak` 存在但损坏时永远无法自愈 | `ensureBackup` 只在 `.bak` 缺失时写；若 `.bak` 因外部原因损坏，之后每次启动都不会刷新它。建议：启动时若 `.bak` 校验失败则用**当前成功加载的配置**覆盖之（仍是"最后一次好配置"语义） |
| P16 | `.bak` 的"陈旧度" | 对纯手工编辑的机器，`.bak` 只在首次成功加载时生成，之后不再更新；自愈会回退到**很久以前**的版本（日志有 mtime 可查，但回退幅度可能很大）。建议二选一：① 每次成功启动都刷新 `.bak`（last-known-good）；② 保留现状但在日志与文档中说明「回退目标为 <mtime> 的备份，可能较旧」 |
| P17 | `pruneBroken` 的排序前提 | 依赖「10 位秒级时间戳 → 字典序=时间序」（2286 年前成立）。建议加一行注释说明，避免后人改成毫秒/纳秒后排序失序 |
| P18 | `design §4.3` 未写"驱动能力不足 → 跳过 vault 根" | 现文档只描述「manifest 缺失/损坏 → 空目录 + 提示」，缺「驱动不支持流式随机读（百度）→ 完全不建根」这一分支。建议补一句，使三态（Reader / URL / 均不支持）与代码一致 |
