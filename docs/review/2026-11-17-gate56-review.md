## 2. 真机修复（c2c5570）复核：方向正确

- **根因正确**：AX6 BusyBox `wget` v1.25.1 无 `-S`，导致 15 次轮询全 `000` → 假失败 → 回滚。改为「进程存活 + 日志新增『Gateway 启动』行」，完全脱离 wget，是对的。
- **新健康检查的推理成立**：`main.go` 在 `slog.Info("...Gateway 启动")` 之后才 `ListenAndServe`；若监听失败会立即 `os.Exit(1)`。因此「启动日志行出现 + 进程仍存活 15 秒」即等价于「监听器已绑定并服务」，比单查端口更可靠，也避开了 wget 的 401 退出码问题。
- **LOG_START 只查新增行**：`tail -n "+$((LOG_START+1))"` + `touch` 建日志，避免历史「Gateway 启动」行造成假通过——细节到位。
- **回滚实战验证**：首轮 wget 误判自动回滚、旧版本 v0.9.2 恢复运行，说明失败路径真实走通过一次，不是纸面逻辑。

## 4. 新增意见

### I12（重要）　唯一未验证项恰好是 v0.10.0 的核心价值

- **事实**：验收清单 §2 第 5 项「更新后挂载**立即**恢复：目录可浏览、文件可播放（无需等 30 秒）」因旧 authorization 未过期而无法真机验证，标注「待生产首验」。
- **为什么是重要**：本版本的头号卖点就是「token 过期 → 打开 /admin 粘贴新值 → 立即恢复、免 SSH」。第 5 项测的正是这条主链路里"从过期态恢复"的那一跳；现在验证过的是"有效 token → 换个新 token 仍有效"（第 4/6 项），**没有验证"过期 → 更新 → 恢复"的完整闭环**。
- **建议**：不必等 30 天真过期。可在真机构造一次过期态：把一个已知过期时间戳的 authorization 写入 config 让挂载先显示「已过期 + 空目录」，再走 `/admin` 更新，验证目录立即恢复。这能离线模拟、几分钟完成，把最后这一跳补上再打 tag（或至少在生产首验后回填结论）。

### I13（建议确认）　`killall` 对 20 字符二进制名的匹配

- **事实**：脚本用 `killall "mini-cloud-arm64-upx"` 停服/回滚。Linux 的进程名（comm）上限 15 字符，此二进制名会被截断为 `mini-cloud-arm64-u`；若 BusyBox `killall` 按 comm 匹配，则杀不到目标进程。
- **缓解现状**：主流程停服后有 `kill -0 $OLD_PID` 的 15 秒确认循环——若 killall 没杀掉，会**安全中止**（不安装），不算事故；但 `rollback_old` 的 `killall || true` 没有确认，失败会落到「回滚后服务仍未恢复，请人工介入」，等于回滚退化。
- **要求**：真机 `ps w | grep mini-cloud` 确认 `killall` 是否真的清掉了进程（你已实测回滚"有效"，请顺带确认这是"真的杀掉了"而非"新旧进程并存"）。若不确定，统一改为 `kill $(pgrep -f "$BINARY") 2>/dev/null || true`（pgrep -f 按完整命令行匹配，AX6 已确认有 pgrep）。

### P19（建议）　「播放 RSS」数据点偏弱

- 播放 RSS 15,836 kB 低于空闲 16,620 kB，说明那次"播放"大概率不是真实 4K 负载（或采样在播放前/结束后）。铁律 10 要的是"播放时"观察值，建议真放一路 4K 时用 `top -b -n1` 或 `grep VmRSS /proc/<pid>/status` 复测一次并回填。

### 8.1 I12 的过期态模拟方法（回答"过期 authorization 从哪来"）

- 无法铸造"服务端真正有效却已过期"的 token（token 是服务端签发的 blob，不能本地 mint）。
- 但"过期态"是**本地判定**：驱动解 Base64 → 取 token 内第 4 个 `|` 段的时间戳 → 与当前时间比较，之后 `List` 在联网前就短路返回空目录、`HealthWarning` 返回过期提示。因此可用"格式合法、时间戳在过去"的假 token 触发过期态（测试 `makeAuth` 即如此构造）：
  `printf 'RCS:<真实账号>:a|b|c|1600000000000' | base64`（在开发机执行，`1600000000000` 是 2020 年的时间戳）。
- **前置条件（关键）**：必须同时删除/移走 `state/移动云盘_token.json`。否则 v0.9.1 的"config 与缓存取较新者"会用缓存里的真 token，config 的假过期 token 被忽略，挂载不会显示过期。
- **待确认的疑问（这本身比 I12 更值得测）**：删掉缓存后，`Init` 会走 `discoverCloudHost`（联网）。若移动云盘路由发现接口在过期 token 下拒绝返回，则服务会**启动失败**而非"显示空目录"——这与 v0.9.2 文档承诺的"过期 → 空目录 + 提示"不符。真机上用假过期 token + 清空 state 试一次即可同时验证两件事：① 服务能否正常启动并显示过期；② 若能，走 `/admin` 用真实 token 更新，补上 I12 的"过期→更新→立即恢复"闭环。测试前先备份 config.json 与 state/。
- **建议**：不为此卡 tag，保留"待生产首验"；等真实 30 天过期时按下列 3 步补验即可：① 确认挂载显示"已过期/空目录"；② 打开 `/admin` 粘贴新授权并更新；③ 立即刷新目录，确认恢复且显示名正常（无需等 30 秒）。
