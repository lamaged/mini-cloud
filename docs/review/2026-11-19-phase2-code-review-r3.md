## 2. 新增发现

### I1（重要，文档未同步）　design §5.1 point 3 仍写「无 `_mc` 子目录 → 非加密目录，普通模式」

- **事实**：`fdc7efe`/`2fd7e55` 只更新了 §5.1 的 **point 1（容器语义）** 与 **point 4（保留名）**（design.md 共 +2/−2 行）。point 3「子根生命周期」里仍保留：
  > 「对象不存在」（子目录无 `_mc`）→ 非加密目录，普通模式（如残留旧树则摘除）
- **冲突**：代码（`classify` + `List`/`Link`）对无 `_mc` 子目录返回 **404 未找到**，不再是「普通模式」（委托 cached 物理视图）。
- **影响**：design 是闸门⑤ 验收的规格来源；point 3 与 point 1/4 的新口径互相矛盾，会误导验收执行（按旧口径会预期"普通模式可见"，实际是 404）。
- **要求**：point 3 的该行改为「对象不存在（无 `_mc`）→ 非加密单元，摘除旧树后**未找到（404）**，与 point 1 的「不认识即不管」一致」。
