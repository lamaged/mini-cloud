## 2. 对 RV-2026-11-20-02 的三处更正（自省）

1. **P1（manifestSem）升级**：我上一轮标"建议改注释或改包级信号量"，低估了它。正确结论是"必须改为进程级共享信号量"。**并补充一个外部审未提、更需 PM 拍板的点**：改成全局后，"2-3 路"默认值是基于**单挂载**场景的观察；PM 真实用法是**跨 2 挂载**（天翼家庭 + 移动），全局 3 可能让"2 播放器 + 1 下载"跨挂载时 503。因此修法 = 共享信号量 + **重拍默认值**（全局 6？还是接受跨挂载排队？）。
2. **补 keygen `--force` 失败路径**：我上一轮遗漏。修复 = 复用既有 `writeFileAtomic`（temp + fsync + rename），失败删临时、旧钥不动；并补"覆盖成功 / 写失败旧钥不变 / 覆盖后 0600 / temp 同目录"4 组测试。
3. **补配置自愈分流**：`Load` 必须区分「JSON 语法错误（`json.SyntaxError`/`*json.UnmarshalTypeError`）」与「语义校验错误（`validateVault` 哨兵）」——仅前者进 `.bak` 自愈，后者直接报错退出。这是我 RV-18-02 强调过、本轮被 `validateVault` 引入时破坏的不变量。

## 4. AX6 评价（认同）

外部审强调「`debug.SetMemoryLimit` 是软目标、非硬上限，不能替代并发与输入大小限制」——正确。由此 R2-1 的必要性成立：**真正的内存护栏应是"进程级 manifest 并发=2 + 进程级解密流=配置值 + 16 MiB 清单上限"三者叠加**，软上限只是最后一道 GC 兜底。
