## 3. 全局并发实测（手册第 3 节，核心）

> 配置口径（PM 拍板 2026-11-20）：**默认 3**（config 缺省），**天花板 4**（>4 启动报错）。两个口径均实测：

### 3.1 C1 跨挂载播放器（电视天翼家庭 + 手机移动）

电视（Nova Player）播天翼家庭 4K/剧集 + 手机（网易爆米花）播移动 4K，同时播放互不干扰、无 503、流畅。**通过**（PM 实测）。

### 3.2 C2 满 3 路下载（PowerShell 并发脚本，移动挂载 3×~600 MB）

| 项 | 实测 |
|---|---|
| 结果 | 3 路全部 OK，无 503 |
| 总吞吐 | 27.45 MB/s ≈ 220 Mbps |
| RSS 峰值 | 53.9 MB（判据 ≤~70 MB ✓） |
| MemFree 最低 | 24.2 MB（判据 ≥~20 MB ✓） |
| CPU 峰值 | ~49% |
| 稳定性 | 无崩溃、结束后回落；平台稳定无泄漏 |

### 3.3 C3 限流（两口径）

**天花板 4 验证**（max_streams=4）：4 路并发（3 移动 + 1 天翼）全部成功——RSS 峰 51.2 MB、MemFree 最低 30.9 MB、无崩溃。天翼第 4 路实测 ~4.9 MB/s（天翼 CDN ~50 Mbps 限速清晰可见，与 2026-11-19 定性一致）。**「天花板 4」实弹通过**。

**默认 3 限流**（max_streams=3 重启后）：

| 观察 | 实测 |
|---|---|
| 第 4 路（PowerShell） | 等待 **5.2 秒**（= 信号量获取超时 5s，分秒不差）后 503，0 MB / OK=False |

### 3.4 C4 释放恢复

3 路保持时取消一路 → 重新发起第 4 路 → 下载成功（6.6 MB/s），内容完整、改名 `.mp4` 后正常播放。**通过**。

### 3.5 「.txt」现象说明（预期行为，非缺陷）

Edge 下载第 4 路被 503 拒绝时，服务器返回的是纯文本错误体（"Service Unavailable"，`text/plain`）——Edge 按错误响应的内容类型给失败下载命名 `.txt`；恢复下载沿用首次登记的文件名，但**文件内容是正确的解密视频流**（改名 `.mp4` 播放正常为证）。这是限流拒绝 + 客户端命名策略的叠加产物，服务器端无任何异常。
