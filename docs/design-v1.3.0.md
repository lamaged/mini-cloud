## 1. 背景与目标

2026-11-23 真机事故：百度 `refresh_token` 失效 → `createAllDrivers` 整体失败 → 进程 `os.Exit(1)` → 8088 端口从未监听 → 天翼/移动/百度全部不可用。追查中发现百度 OAuth 凭据硬编码于源码（公共凭据）。由此提出本轮三项目标：

1. **A 启动隔离（P0）**：单挂载初始化失败不拖垮其他挂载；至少一个挂载成功即提供服务。
2. **B 状态红绿灯（P0）**：首页每个挂载框以颜色表达状态（失效=红、警告=黄、正常=黑色不动），管理页可操作；现有「提示性显示名」按 PM 拍板移除。
3. **C 百度 OAuth 维护（P1，按审核 D2 拆两批）**：**批 1** 交付「百度凭证更新通道」——移除源码内置凭据、用户自有应用凭据必填、配置写回支持百度、管理页粘贴 `refresh_token` 输入框（审核 D2：输入框必须整链路可用）；**批 2** 交付一键授权（授权码手工回填）与刷新链路加固（互斥、轮换原子落盘、凭据代次、失效恢复）。

**D 百度加密（P1，初稿 §5）不纳入本轮**：改铁律不是障碍（PM），障碍是开发成本与收益不确定性（百度 CDN Range 行为、会员/非会员差异）——需先单独出可行性论证（真机实测数据），再由 PM 拍板，不做则不写。

## 4. 设计：A 启动隔离（批 1）

### 4.1 目标行为

- 逐个创建/初始化挂载；单挂载失败只记录该挂载状态，不中断流程。
- 至少一个挂载成功 → 正常启动 HTTP 服务，仅注册成功挂载的路由。
- 失败的挂载保留在状态表中（首页红色）；**驱动实例同样保留并进入 /admin 状态列表**（审核 D1：否则失败挂载的管理页入口丢失，百度票失效后无法网页更新，只能 SSH）。
- 支持 `CredentialUpdater` 的失败挂载仍可在管理页更新凭据；**更新成功 ≠ 恢复**（审核 D3）：状态保持红色 + 提示「已保存，重启后生效」，重启初始化成功才转正常。
- 失败挂载**不做自动重试**（第一阶段）：重启进程重新初始化。第二阶段「低频退避重试 + 动态启用路由」列为后续可选（初稿 §2.6 采纳），本轮不实现。

### 4.2 数据模型

```go
type MountStatus string

const (
    StatusUnknown     MountStatus = "unknown"     // 仅内部状态；页面按 HEALTHY（黑色）展示（PM 拍板：无灰色档）
    StatusHealthy     MountStatus = "healthy"     // 正常（黑色）
    StatusWarning     MountStatus = "warning"     // 警告（黄色）
    StatusUnavailable MountStatus = "unavailable" // 失效（红色）
)

type MountRuntime struct {
    Config     CloudConfig
    Name       string
    Prefix     string
    RawDriver  driver.Driver // 创建成功即保留；Init 失败也保留（/admin 凭证更新入口，审核 D1）；创建失败为 nil（无更新入口，审核 RV-26-24-02）
    InitError  error         // 创建或初始化失败原因（脱敏后入 LastError；RawDriver == nil 即创建失败）
    Available  bool          // Init 成功且 WebDAV 路由已注册

    mu            sync.RWMutex // 审核 I3：以下状态字段并发保护（探测 goroutine 写、HTTP 页读）
    Status        MountStatus
    LastError     string    // 脱敏、限长（≤200 字符）
    LastCheckAt   time.Time // 最近一次健康探测时间
    LastSuccessAt time.Time // 最近一次探测/访问成功时间
    UpdatedAt     time.Time
}
```

- 断言一律对 `RawDriver`（原始驱动，铁律 7）；`Init` 失败时不注册数据路由，但保留 `/admin` 状态卡与凭证更新入口。
- **两个集合**（审核 RV-26-24-02）：**状态表 = 全部配置挂载**（无论创建/初始化成功与否）——首页与 /admin 只渲染它；**数据路由 = 仅 `Available == true` 的挂载**注册（WebDAV 数据路径只走这里）。诊断首页（Q1 已拍板）同样基于状态表，全失败时能看到每个挂载的红色状态，而不是「0 个云盘」。
- 凭证更新表单仅对「创建成功（RawDriver 非 nil）且实现 CredentialUpdater」的挂载提供；创建失败的挂载只显示配置/错误诊断，不给更新入口。
- 状态为运行期数据，与配置分离；敏感凭据永不进入状态输出。
- 并发（审核 I3）：探测完成后以**完整快照一次性替换**状态字段，HTTP 页面只读快照，不逐字段读正在变化的值；`go test -race` 必过。

### 4.3 初始化流程与错误分级

```text
加载并校验全局配置（JSON 损坏/监听非法/认证非法 → 全局错误，退出）
        |
        v
结构校验（本轮新增，审核 P1 细化 + 安全审核 RV-26-24-06 附加固）：挂载名非空、唯一、
        |   不含路径分隔符（`/` `\`）、控制字符、空格、`{}`、`%`（Go 1.22+ ServeMux
        |    模式语法保留字符——防启动 panic 与路由别名）、不为 `.` 或 `..`、长度 ≤64；
        |    中文合法（现有挂载名均为中文）
        |   （违例 → 全局错误 fail-fast，与 vault.paths 校验同口径）
        v
逐个处理 clouds：创建失败 → StatusUnavailable + LastError，RawDriver 为 nil，继续
        |         Init 失败 → StatusUnavailable + LastError，RawDriver 保留，继续
        |         Init 成功 → Available=true，注册 WebDAV 路由 + 启动 Token Watcher
        v
启动 HTTP Server（至少一个成功 → 正常服务；零成功 → 诊断首页，Q1 已拍板：起）
        |
        v
首页与 /admin 基于「全部配置挂载」的状态表渲染（审核 RV-26-24-02：不是成功列表——
        全失败时首页也能看到每个挂载的红色状态，而不是「0 个云盘」）；
        WebDAV 数据路由仅注册 Available == true 的挂载
```

| 错误类型 | 处理方式 | 阻止进程 |
|---|---|---|
| 配置文件不存在且无法创建、JSON 损坏 | 全局错误 | 是 |
| server.listen 非法、全局认证非法 | 全局错误 | 是 |
| 挂载名重复/非法（本轮新增校验） | 全局错误 fail-fast | 是 |
| 某挂载 type 不支持 / 缺必需凭据 / OAuth·session 初始化失败 / 上游暂不可达 | 该挂载 UNAVAILABLE，继续 | 否 |
| Token Watcher 后续刷新失败 | 更新挂载状态与告警 | 否 |

### 4.4 验收标准

1. 百度 refresh_token 故意失效 → 天翼/移动仍可正常访问。
2. 任一挂载 `Init()` 返回错误 → 其他挂载仍注册路由。
3. 多挂载同时失败 → 日志逐个指明挂载名、类型、错误原因。
4. 全部挂载失败 → 诊断首页仍可访问，且显示**全部配置挂载**的红色状态（非「0 个云盘」；Q1 已拍板 + 审核 RV-26-24-02）。
5. 单挂载失败不造成进程退出、端口不监听或其他挂载缓存被关闭。
6. 失败挂载在 /admin 可见；支持 CredentialUpdater 者可更新凭据，更新后提示「已保存，重启后生效」，状态保持红色直至重启成功。
7. `go test -race` 全绿（状态并发安全，审核 I3）。
8. 创建失败的挂载（RawDriver 为 nil）进入状态表显示红色诊断，但不显示凭证更新表单（审核 RV-26-24-02）。

## 5. 设计：B 状态红绿灯（批 1）

### 5.1 首页展示

- **布局与显示不变**：仍是挂载卡片列表；**颜色落在挂载名文字上**（状态类 `ok`/`warning`/`error` 只改文字颜色，**不改变卡片背景**，审核 I4）；正常挂载保持原有样式。颜色语义：黑=正常、黄=警告、红=失效；无灰色。
- 卡片内容：**仅挂载名**（desc 行保留原 href 展示）。**首页不显示错误原因**（审核 I4）——原因与处理信息只放 /admin。`displayName` 简化为纯挂载名——首页与根 PROPFIND 的告警拼接一并移除（PM 拍板 §3.4）。
- 初始化失败**立即红色**，不等健康探测（审核 I4）；`StatusUnknown` 仅内部状态，页面按正常黑色展示。
- **红卡不可点击**（PM 拍板 2026-11-25，真机验收反馈）：不可用挂载渲染为不可点的卡片（无数据路由，点击必 404）；正常/警告挂载保持链接。
- 「管理」链接：`hasAdmin && 存在任一非 HEALTHY 挂载` 才显示。
- 状态消息脱敏 + 限长；所有 HTML 输出沿用现有转义（html.EscapeString）。
- 首页不做自动刷新（PM 拍板）；不做 /admin/api/status JSON 接口（初稿 §3.5 有，本轮砍：首页服务端直接渲染状态快照，无消费方）。
- /admin 状态卡升级为结构化状态展示（颜色点 + 文字 + 最近检查时间），继续双通道（驱动健康 + Vault 告警）。

### 5.2 结构化健康模型

```go
// 审核 I1：职责拆分——驱动只报「事实」（凭据到期时间、是否已失效、警告文本），
// 不报最终健康结论；红黄黑由应用层统一合成（全项目唯一判定规则）。
type DriverHealth struct {
    Warning     string     // 空 = 无警告；人读文案（如「刷新失败，会话暂可用」）
    ExpiresAt   *time.Time // 凭据到期时间（驱动能可靠解析时提供）
    AuthExpired bool       // 审核 RV-26-24-02：凭据已失效/不可恢复（区别于「临近到期」）
}

// HealthReporter 升级（原 HealthWarning() string 废弃，移动迁移至此）：
// 断言对象必须是原始驱动（铁律 7）；Vault 与 CachedReader 不得实现。
type HealthReporter interface {
    Health() DriverHealth
}
```

- 迁移面：仅移动实现 + main.go 两处消费点，面小；升级不保留双接口。
- **状态合成规则全项目唯一**（应用层）：挂载状态 = f(初始化结果, 探测结果, DriverHealth)；驱动与首页不得各自判断颜色。
- 事实 → 状态映射（审核 RV-26-24-02，不用文字关键词判色）：

| 驱动事实 | 状态 |
|---|---|
| `AuthExpired == true`（已过期 / 不可恢复失效） | 红（UNAVAILABLE） |
| 临近到期（如剩 <7 天） | 黄（WARNING） |
| 刷新失败但当前会话暂可用 / 受限模式 | 黄（WARNING） |
| 无任何警告事实 | 由探测结果决定黑/红 |

- 合成规则：
  - 初始化失败 → UNAVAILABLE（立即红，不等探测）；
  - **`AuthExpired` → UNAVAILABLE，优先级最高：一次 List 成功不得覆盖已确认的凭据失效**（审核 RV-26-24-02）；
  - 探测连续 2 次失败（连接/认证/上游类）→ UNAVAILABLE；单次失败不转红；
  - `DriverHealth.Warning` 非空且未失效（临近到期、受限模式、刷新失败但会话可用等）→ WARNING；
  - **探测「成功」不足以判 HEALTHY**（审核 I2）：移动在 authorization 过期/受限模式下 `List` 返回 `(nil, nil)` 无错误（drivers/mobile/driver.go:206-209）——探测判据必须同时检查 `DriverHealth`，有警告/失效事实时不得因 List 无错判正常；
  - 最近探测成功且无警告 → HEALTHY；一次成功探测即可从黄恢复（红仅当失效事实消失或重启初始化成功）；
  - 首次探测完成前 → 按 HEALTHY 显示（无灰色档，StatusUnknown 仅内部存在）。

### 5.3 健康探测

- 每挂载独立，默认每 5 分钟（启动后立即一次）；独立 ctx 超时 ≤10s；同一挂载同一时刻最多一个探测（单飞）。
- 探测内容：`List` 根目录（raw 驱动直调，**绕过 CachedReader 缓存**，避免旧缓存掩盖上游状态）；不下载文件、不遍历目录。
- **探测判据（审核 I2 + RV-26-24-02）**：`err != nil` → 计失败；`err == nil` 但 `DriverHealth` 有警告 → 不得判健康，按警告/失效规则处理；`AuthExpired` → 直接 UNAVAILABLE，探测结果不得覆盖；探测结果不更新缓存、不刷新 `LastCheckAt` 的缓存命中口径。
- 并发（审核 I3）：探测 goroutine 写、HTTP 页读——每挂载状态对象持 `sync.RWMutex`，探测完成后快照一次性替换（§4.2）；`go test -race` 必过。
- 本轮**不做失败退避**：5 分钟已是低频，退避逻辑省去（设计决定；真机验收观察探测开销）。
- 上游限流（审核 P2）：探测遇 429/限流类错误计入失败并分类 `RATE_LIMITED`，不误判正常（测试矩阵 A12）。
- 正常 WebDAV 请求成功可更新 `LastSuccessAt`；单次文件读取失败不等于挂载不可用。
- 「即将过期」判定按驱动分别（初稿 §3.4 采纳）：移动解析 authorization 真实过期时间，剩 <7 天 → 黄（解析能力已存在，v0.10 管理页剩余有效期显示）；天翼无可靠到期时间不虚构，刷新失败/API 明确拒绝才转红/黄；百度见 §6.10。

### 5.4 验收标准

1. 百度 token 故意失效 → 首页百度框红色、天翼/移动黑色，可正常访问。
2. 移动 authorization 剩 <7 天 → 黄色；过期 → 红色（或按现行过期语义对齐，见 §5.3）。
3. 全部正常 → 全黑、首页无「管理」链接；任一挂载异常 → 「管理」链接出现。
4. 首页与根 PROPFIND 显示名均为纯挂载名（无告警拼接）。
5. 探测对云盘 API 的调用量与 AX6 负载可接受（真机观察项）。
6. 挂载名含 HTML 特殊字符 → 首页正确转义显示。
7. 移动 authorization 过期但 List 返回 `(nil, nil)` → 不得判正常（审核 I2；与受限模式、正常空目录三场景区分，测试矩阵 A09-A11）。
8. 状态并发：探测与页面同时访问 → 无数据竞争，`go test -race` 全绿（审核 I3）。

## 6. 设计：C 百度 OAuth 维护（批 1 通道 + 批 2 加固）

范围按外部审核 D2 拆分（PM 拍板 §3.9）：**批 1 = 百度凭证更新通道**（凭据必填、配置写回、输入框——输入框必须整链路可用）；**批 2 = 一键授权 + 刷新链路加固**。

### 6.1 批 1：配置凭据基础

- 删除源码内置 `DefaultClientID`/`DefaultClientSecret` 及空值回退（PM 拍板；CLAUDE.md「内置 OAuth 默认凭据」例外条款随代码删除同步清理）。
- `client_id`/`client_secret` **必填**（百度网盘开放平台应用：AppKey → client_id、SecretKey → client_secret）；conf 校验缺失 → 该百度挂载红色「OAuth 应用凭据未配置」，不影响其他挂载；**不静默回退**。
- `refresh_token` 可空（= 尚未授权，红色 + 管理页可贴）。
- 迁移：旧配置 client_id/secret 为空 → 升级后百度挂载红色 + /admin 填写指引；PM 部署批 1 前需在 config 填入自有 AppKey/SecretKey。

### 6.2 批 1：输入框全链路（审核 D2）

| 环节 | 交付内容 |
|---|---|
| 管理页 | 百度卡片新增 refresh_token 输入框（与移动同交互） |
| 百度驱动 | 实现 `CredentialUpdater`（两阶段，internal/driver/driver.go:64+ 契约；断言对原始驱动，铁律 7） |
| 验证 | `ValidateCredential` 调用**无副作用 token 交换函数**（审核 RV-26-24-02 阻断项）：只请求并返回 access_token/refresh_token/expires_in，**不修改客户端内存**——现 auth.go `refreshToken()` 内置 `c.SetAccessToken`（先改内存）必须先拆分为纯交换函数；验证响应含新 refresh_token 时经保留键传给 Commit（见下表后契约），**不丢弃** |
| 配置写回 | `conf.WriteCredential` 扩展：支持写百度 `refresh_token`（现仅支持移动 authorization）——原子写（临时文件+落盘+改名）+ .bak + 0600 沿用现制；写入值为**验证后的最终 refresh_token**，非表单原始输入 |
| 内存更新 | **顺序：验证 → 写配置 → 改内存**（审核 RV-26-24-02）：config 持久化成功后才提交客户端内存凭据（互斥锁 getter/setter，铁律 8） |
| 失败处理 | 见下表后「提交结果语义」（审核 RV-26-24-04：state 缓存写失败不回滚已生效凭据） |
| 重启恢复 | 新凭据重启后经 Init 生效 |

**验证结果传递契约（审核 RV-26-24-03 阻断项）**：现有接口 `ValidateCredential(ctx, values map[string]string) error` 无独立返回值——沿用现有保留键机制（`__req`/`__expiry` 同款）：

1. 验证成功后，把**最终 refresh_token**（百度可能轮换过的新值）写入 `values` 的专用保留键 `__refresh_token`；
2. 配置写回（PersistFunc）使用该最终值，而非表单原始输入；
3. `CommitCredential` 用同一最终值更新内存凭据——验证、写配置、改内存三环节同一值；
4. 验证失败不得在 `values` 中留下任何可被后续误用的残余值；
5. `__refresh_token` 不得在管理页回显、不得写入日志。

**提交结果语义（审核 RV-26-24-04，与现有接口契约对齐）**：现有 `CommitCredential` 契约——token state 写入失败时凭据仍然生效、返回 `ErrStateWriteFailed`，管理页视为已提交成功（不回滚配置）。「零变化」只适用于验证与配置写入两个环节：

| 结果 | 配置 | 内存凭据 | state 缓存 | 处理 |
|---|---|---|---|---|
| 验证失败 | 不变 | 不变 | 不变 | 返回失败 |
| 配置写入失败 | 不变 | 不变 | 不变 | 返回失败 |
| Commit 真正失败 | 回滚（WriteCredential 已备 .bak） | 不生效 | 不变 | 返回失败 |
| ErrStateWriteFailed | 保留新配置 | 保留新凭据 | 可能未更新 | 视为已提交 + 记录缓存告警（state 为纯缓存，下次重新兑换） |

### 6.3 批 1：更新 ≠ 恢复（审核 D1/D3 闭环）

- 初始化失败的挂载**保留驱动实例**于运行状态表（`MountRuntime.RawDriver`，§4.2）：不注册 WebDAV 数据路由，但进入 /admin 状态列表；若驱动支持 `CredentialUpdater`，管理页仍可更新凭据。
- 更新成功只代表「新凭据已验证并保存」。**恢复语义按挂载类别区分**（复核 2026-11-25 定稿，防误读）：
  - **Init 失败的挂载**（InitError 非空，如百度未授权/刷新失败）：状态**保持红色** + 管理页提示「已保存，重启后生效」；重启后重新初始化——成功 → 转正常，仍失败 → 继续红色 + 原因。不做动态路由热启用。
  - **已初始化挂载**（如移动凭据失效致红，Init 本身成功）：提交成功后**按当前健康事实立即重算状态卡**（`refreshSnapshotFromFacts`，PM 拍板 2026-11-25 真机反馈）——事实干净则当场转正常（旧行为即立即生效），无需重启。

### 6.4 批 2：一键授权（授权码手工回填，审核 I5）

```text
管理页「开始授权」→ 服务端生成随机 state（一次性、10 分钟有效、与挂载绑定，服务端留存）
     → 返回百度授权 URL（redirect_uri 按百度网盘开放平台控制台配置，开工前实测定值）
     → 用户登录百度并授权 → 浏览器回跳到显示授权结果页
     → 用户将回调页完整地址复制回管理页粘贴（地址中同时含 code 与 state）
     → 服务端解析并校验 state（存在、未用、未过期、挂载匹配）
     → 服务端以 code + client_id + client_secret 兑换 token（HTTPS、10s 超时）
     → 调轻量用户信息接口验证 token 有效 → 原子落盘（refresh/access/expires_at）
     → 挂载状态恢复（挂载已可用则即时生效；不可用则提示重启）
```

- **code 与 state 必须成对回填**（审核 I5）：回调页地址同时含两者，用户粘贴整条地址、服务端解析——否则服务端无法验证授权响应与当前授权事务匹配。
- 授权码只由服务端兑换；浏览器不接触 client_secret；授权过程必须经现有管理认证（Basic Auth + CSRF）。
- 命名「授权码手工回填流程」；redirect_uri = **`oob`**（PM 控制台已填、实测生效）。
- **Q2 实测（2026-11-25 真机）**：oob 模式下百度在授权页内**以文字展示授权码**（一次性、10 分钟，带「复制授权码」按钮），地址栏 URL **不含 code** 但保留 state——回填改为**两个输入**：「授权码」（码框，复制百度页面的码）+「地址栏网址」（state 取自网址）；code 与 state 成对校验保持（I5 契约不变）。
- 不自动覆盖其他百度挂载的 token（状态文件按挂载名隔离，现制已满足）。

### 6.5 批 2：token 优先级与持久化模型（审核 I6 + RV-26-24-02 重定稿）

**模型**：`config.json` = `refresh_token` 的**唯一真值源**（原子写）；`state/<挂载名>_token.json` 降级为**纯缓存**（access_token/expires_at，可随时丢弃重建——重新兑换即可，无需恢复协议）。

**两个代次字段**（消除原稿「提交/轮换同 +1」矛盾）：

| 字段 | 何时 +1 | 作用 |
|---|---|---|
| `credential_generation` | 仅用户主动提交（管理页粘贴/一键授权） | 防旧的后台轮换结果覆盖新授权 |
| `token_revision` | 仅后台轮换成功 | 识别同一授权代次内的 token 更新 |

**存储位置（审核 RV-26-24-03）**：两字段存于 config 的百度 `CloudConfig`——**新增可选元数据字段**（配置元数据，非 token 缓存，§6.8）；初始值 0；旧配置未填写按 0 迁移（向后兼容）；用户提交时 `credential_generation` +1、`token_revision` 置 1；后台轮换仅 `token_revision` +1。

**写入与恢复规则**（审核五问逐一作答）：

1. 用户提交：`credential_generation` +1、`token_revision` 置 1，原子写 config；成功后改内存；state 缓存随之作废（下次 Init 重新兑换）。
2. 后台轮换：`token_revision` +1，**先原子写 config**（新 refresh_token），再更新 state 缓存；`credential_generation` 较小的迟到轮换结果**不得**写回 config（防旧刷新覆盖新授权）；**「比较代次 → 写回 config」必须在同挂载刷新/凭据更新互斥范围内完成**，防并发打断（审核 RV-26-24-03）。
3. 断电恢复：config 与 state 内容不一致 → **以 config 为准**（唯一真值源）；state 缓存的 access_token 过期/不一致 → 重新兑换，无数据丢失。
4. 同代次内容不同：不可能出现（config 唯一真值源，state 只镜像）；若检测到（文件损坏迹象）→ 按 config 为准 + 记告警。
5. 写失败：内存不提交新值，按旧值续用；状态黄/红（持久化失败）+ 日志 Error。

### 6.6 批 2：Token 持久化与刷新规则（初稿 §4.5 采纳 + 审核 P2 加固）

1. 同挂载刷新互斥（单飞）；401 回调与后台 watcher 的并发刷新进同一把锁。
2. 刷新响应含新 refresh_token → 轮换并按 §6.5 代次写回；无则保留旧值。
3. 原子写：临时文件 + rename；文件 0600、**目录 0700**（现 SaveToken 为 MkdirAll 0755 + os.WriteFile 非原子，实现时重构，见 6.7）。
4. 落盘失败 = 严重错误：日志 Error + 状态黄/红；**不得**记为「刷新成功」；**Init、后台 watcher、401 回调三条路径都必须传播持久化错误**（审核 P2）。
5. 内存 token 与磁盘 token 提交顺序明确：先落盘成功，才提交内存新值。
6. API 401/errno 失效 → 自动刷新并重试一次，防递归。
7. 连续刷新失败限频（如最短 60s 间隔），防每个 WebDAV 请求都触发 OAuth。
8. 不可恢复错误（`expired_token`/`has been used`）→ 红色「需要重新授权」+ 管理页入口；临时网络错误 → 黄色 + 退避重试。

### 6.7 批 2：实现层重构要求（审核 P2）

- `RefreshToken(ctx)` 必须真正使用传入 ctx（超时/取消可传导），不能只在调用方设置超时。
- 重构 `auth.go` 刷新函数职责（审核 P2 + RV-26-24-02）：现 `refreshToken()` 直接调 `c.SetAccessToken()`（先改内存）、`SaveToken()` 为 `os.WriteFile` 非原子——拆分为「**纯 token 交换函数（无副作用，批 1 验证也用它）→ 原子落盘（先 config 后 state）→ 提交内存**」三步；state 文件仅存 access_token 缓存（§6.5 模型），refresh_token 唯一真值源为 config。
- token 状态文件新增格式版本字段（向后兼容）。

### 6.8 配置与迁移

- config 百度段：`client_id`/`client_secret`/`refresh_token` 字段不变，语义变更——前两者必填、refresh_token 可空（批 1 生效）；**新增两个可选元数据字段** `credential_generation`/`token_revision`（配置元数据而非 token 缓存，§6.5；旧配置未填写按 0 迁移，向后兼容）。
- config.example.json 与 README 附录 A 百度行重写（申请入口：百度网盘开放平台 pan.baidu.com/union；字段对应：AppKey→client_id、SecretKey→client_secret、AppID/SignKey 不使用）。
- 状态文件格式不变（state/<挂载名>_token.json），新增字段向后兼容。

### 6.9 安全要求（初稿 §4.7 采纳 + 审核 P2）

- 日志只输出挂载名、错误码、错误类别；不输出 token/secret/授权码/完整授权 URL。
- token 交换用 HTTPS + 合理超时（ctx 传导）；state 随机、短时、一次性。
- token 文件 0600、目录 0700、原子写。
- 状态输出（首页/管理页）不回显任何凭据字段。
- 授权流程除 httptest 外，保留 PM 自有百度应用真机验证（审核 P2）。

### 6.10 状态映射（与 §5.2 合成规则衔接）

| 条件 | 状态 |
|---|---|
| client_id/secret 缺失 | 红：OAuth 应用凭据未配置 |
| refresh_token 缺失 | 红：尚未授权（管理页可授权） |
| 更新成功但未重启（挂载当前不可用） | 红：「已保存，重启后生效」 |
| access_token 正常、无风险 | 黑 |
| 刷新失败但会话暂可用 / 即将过期 | 黄 |
| refresh_token 不可恢复失效 / 落盘失败 | 红：需要重新授权 / 存储异常 |

### 6.11 验收标准（httptest 假服务器；第 10 条 PM 应用真机）

1. 不配置 client_id/secret → 百度挂载明确失败（红），其他云盘正常启动。
2. 配置自有应用 + 贴 refresh_token → 验证通过、原子落盘、重启后恢复。
3. 验证失败 → 配置、内存、状态零变化。
4. access token 到期前主动刷新成功（现有 watcher 机制延续）。
5. 模拟百度返回新 refresh_token → 新 refresh_token 原子写 config（`token_revision` +1）、state 仅更新 access_token 缓存、重启后使用新值。
6. 模拟迟到的旧代次刷新结果（`credential_generation` 较小）→ 不得写回 config，新授权不被覆盖。
7. 模拟 refresh_token 失效 → 红色 + 重新授权入口，其他云盘不受影响。
8. 模拟 token 文件不可写 → 三条路径（Init/watcher/401）均报持久化错误，状态准确。
9. 并发请求同时触发失效 → 同挂载仅一次有效刷新，无刷新风暴。
10. 一键授权全流程（state 校验/兑换/落盘/恢复）——PM 百度应用真机走一遍（不可用则执行降级路径并记录）。
11. 验证返回新 refresh_token → 写配置与内存更新使用同一最终值（保留键 `__refresh_token` 传递），页面不回显、日志不记录。
12. 断电 / state 缓存缺失或不匹配 → config 保留最新 refresh_token；state 缓存丢弃重新兑换，数据不丢。

### 6.12 批 2 附项：管理页重启服务（PM 拍板 2026-11-25 并入批 2）

背景：无守护进程（PM 拍板）；「已保存，重启后生效」（D3）与配置手工修改都需要重启，而重启目前只能 SSH——管理页提供一键重启。

- 行为：`POST /admin/restart`（Basic Auth + CSRF，复用现有防护）→ 页面提示「正在重启」→ 约 1 秒后进程**原地重启自身**（`syscall.Exec` 执行 `/proc/self/exe` + 原启动参数）：PID 不变、日志文件描述符继承（日志连续）、init.d 的 PID_FILE/RUN_FLAG 继续有效。
- 安全：不执行任何外部命令、不接受任何用户输入；仅认证管理员可触发（其本可通过 SSH 重启，不新增权限面）；无 CSRF 令牌或未认证一律拒绝。
- 兜底：`syscall.Exec` 失败（个别文件系统限制）→ 页面如实提示手工重启（中性文案，不硬编码设备侧管理脚本路径——审核 P2-2：实际部署由设备侧统一进程管理）。
- 验收：①点击重启后服务恢复（日志「Gateway 启动」+ 首页可访问）；②未认证/无 CSRF → 拒绝；③重启后 PID 不变、设备侧进程管理脚本仍可用；④AX6 真机走通。

## 8. 不改动范围（铁律守护）

- 只读 WebDAV（铁律 3）；未加密路径 302 行为不变（铁律 7）。
- Vault 格式、支持范围（tianyi/mobile/local）、`vaultSupported` 一律不动；mcrypt 工具不动。
- 百度 `Link()` 代理下载实现不动（OAuth 凭据字段相关代码除外）。
- 包装层（Vault/CachedReader/RetryReader）不得实现新可选接口；断言对象必须为原始驱动。
- 单账户单用户（铁律 1）；不引入外部依赖（铁律 6）；不引入数据库/消息队列/守护进程。
- D 百度加密：不纳入本轮（§1）。

## 12. 风险

1. **健康探测增量调用**：5 分钟 × 挂载数 × List 根目录——低频轻量，真机验收观察 AX6 负载与云盘接口风控（含 429 限流）。
2. **授权码手工回填可行性不确定**：百度开放平台对回调方式的限制可能变化——降级路径已备（§6.4），不影响批 1。
3. **接口升级迁移面**：HealthReporter 仅移动实现 + main 两处消费点，面小；升级后逐一核对 401 回调注册顺序等既有不变量（CLAUDE.md 已记历史教训）。
4. **铁律 2 修订**：百度纳入正式维护后，百度挂载缺陷按正式功能处理（PM 已知悉）。
5. **移动过期语义对齐**：现有「过期返回空目录」行为与「红色失效」展示需对齐表述（状态红、目录空、/admin 指引），避免两处语义打架；探测判据按 I2 不得把空目录误判健康。
6. **批 1 范围扩大（PM 拍板）**：百度内置凭据删除后，PM 部署批 1 时 config 必须已填自有 AppKey/SecretKey，否则百度挂载红色「应用凭据未配置」——属预期行为，README/管理页需给足指引。
