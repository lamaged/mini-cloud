### mcrypt 命令速查（Windows，管理员 PowerShell/CMD）

```bat
:: 生成主密钥（仅首次；已存在会拒绝，--force 才覆盖——覆盖=全部已加密数据作废！）
mcrypt.exe keygen -key vault.key

:: 加密一个目录（生成 上传目录\_mc\）
mcrypt.exe encrypt -key vault.key -in 明文目录 -out 上传目录

:: 解密还原（验证用；拒绝输出路径中的快捷方式目录）
mcrypt.exe decrypt -key vault.key -in vault根目录 -out 明文输出目录

:: 完整性校验（不输出明文，只核对 SHA-256）
mcrypt.exe verify -key vault.key -in vault根目录
```

> 注意：`vault.key` 必须是**同一把**（与加密云盘文件时用的完全一致）；上传新单元后 ≤5 分钟自动生效（免重启）。

## 3. 全局并发验收（核心项，对应全局并发 3 拍板）

> 背景：并发额度现在是**全进程共享**（三挂载合计最多 3 路解密流）。以下用例实测跨挂载排队的真实体验。

| 用例 | 操作步骤 | 判定标准 |
|---|---|---|
| C1 双挂载各 1 播放器 | 电视播天翼家庭 4K + 手机播移动 4K | 两路都流畅，无 503 |
| C2 双挂载 + 下载（= 3 路满） | 在 C1 基础上电脑 Edge 下载一个加密文件 | 三路均正常；**若其中一路出现 503/失败，记下是哪一路、什么现象**（这是全局化后最需要实测的关键点） |
| C3 第 4 路验证限流 | C2 保持三路，再开一个新播放（任意端） | 第 4 路应被拒绝（503 或无法打开）——**限流生效是设计行为，记下现象即可，不算缺陷** |
| C4 排队恢复 | 关闭 C3 的新播放后，重新打开它 | 应恢复可播（额度释放后可用） |

## 4. 容器自动发现（核心功能）

- [ ] **新增**：加密一个小目录 → 上传到某云盘 `backup/新名字/` → **等 5 分钟**（期间可正常浏览该容器路径触发扫描）→ 浏览器刷新可见新单元，可播放
- [ ] **删除**：云盘删除一个单元到回收站 → 5 分钟后浏览，该单元消失、无报错
- [ ] **恢复**：回收站恢复 → 5 分钟后单元重现、可播放
- [ ] **整块换新**：删除旧单元 + 上传新单元 → 列表更新、新内容可播
- [ ] 上述操作期间，正在播放的视频不受影响

## 附：异常速查

| 现象 | 含义 | 处置 |
|---|---|---|
| 部署后加密目录全空 | 旧结构未迁移（`backup/_mc` 直接存在） | 云盘把 `_mc` 移进子目录，5 分钟后自动恢复 |
| /admin 有橙色警告 | 对应挂载存在需要处理的问题 | 按警告文案处理（迁移/更新凭证/修复清单） |
| 某播放 503 | 并发额度满（全进程 3 路） | 关掉一路再试；若 2 路就 503 则记录日志交程序员 |
| 启动失败 | 配置校验不通过（如 max_streams>4、paths 含多段） | 日志有明确原因，按提示改 config.json |
| 部署脚本报「can't open mini-cloud.log」 | 日志文件被 rm 删除（请用 `>` 清空而非 rm） | `touch /data/mini-cloud/mini-cloud.log` 后重新部署；新版脚本已自动重建 |
